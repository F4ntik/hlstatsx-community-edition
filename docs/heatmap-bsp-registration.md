# Как точно совместить тепловую карту с BSP

Координаты событий уже находятся в системе координат игровой карты. Ошибка
возникает при переводе этих координат в пиксели картинки. Растянуть точки так,
чтобы все они помещались в изображение, недостаточно: точки могут оказаться
в другом коридоре или на другой базе.

Для Counter-Strike 1.6 используйте три файла одной версии карты: `maps/<map>.bsp`,
`overviews/<map>.txt` и `overviews/<map>.bmp`. Ещё нужен точный JPG, который
показывает сайт. Его поля и размер могут отличаться от оригинального BMP.

## Порядок проверки

1. Возьмите BSP и пару BMP/TXT из установленной игры или с того сервера,
   чьи события анализируете. Одинаковое название карты не гарантирует одинаковую
   геометрию; сохраняйте контрольные суммы файлов.
2. Запустите локальную проверку ниже. Она извлечёт реальные контуры поверхностей
   и точки появления игроков из BSP, совместит их с BMP по правилам движка,
   затем найдёт соответствия между BMP и JPG сайта.
3. Откройте `bsp-native-overlay.png` и `bsp-served-overlay.png`. Бирюзовые линии
   должны проходить по соответствующим стенам, площадкам и ящикам. Синие и
   красные точки показывают места появления команд. Проверьте разные части карты.
   Линии за краями изображения возможны: BSP содержит невидимые поверхности,
   крыши и закрытые области. Это не карта проходимости.
4. Проверьте численный отчёт: соответствия изображений должны покрывать все
   четыре четверти. Контрольные точки изображения не участвуют в подборе
   преобразования. Не путайте их с контрольными игровыми событиями.
5. Проверьте на отдельной копии статистики несколько реальных событий в известных
   местах. Только после этого сохраняйте настройки через обычный инструмент
   администратора. Локальная проверка сама не изменяет базу или настройки игры.

Если обзорная картинка отсутствует, программа не угадывает её положение по
размаху событий. Если изображения повёрнуты произвольно или растянуты по осям
по-разному, нужен другой исходный рисунок либо отдельная ручная привязка.

## Запуск

Нужны Python, Pillow; для автоматического сопоставления двух картинок также
OpenCV (`opencv-python-headless`). Зависимости желательно ставить в отдельное
окружение, чтобы не менять окружение рабочего сервера.

```text
python scripts/heatmap_bsp_registration.py --bsp "<game>/maps/de_dust2.bsp" --overview "<game>/overviews/de_dust2.txt" --native-image "<game>/overviews/de_dust2.bmp" --served-image "heatmaps/src/cstrike/de_dust2.jpg" --output "<private-output>"
```

Каталог результата содержит отчёт JSON, два PNG с наложением и два SVG с
извлечёнными контурами. PNG включают локальную игровую картинку: оставляйте их
в личном каталоге проверки. SVG не содержат текстур или встроенных растровых
изображений. Программа предназначена для локальных файлов оператора, а не для
публичной загрузки недоверенных BSP на веб-сервер.

Отчёт автоматически включает `candidate_config`: настройки для указанного JPG
(либо BMP, если JPG не задан). Он также проверяет их настоящей функцией
преобразования продукта на координатах вершин BSP и записывает ошибку округления
в `python_roundtrip`. Эти поля не нужно рассчитывать или дописывать вручную.
Запускайте инструмент из корня проекта в окружении с зависимостями продукта.

## Все карты из установленной Counter-Strike

Для 25 стандартных карт шаблоны уже входят в проект: выберите карту в админке
и нажмите **«Показать геометрию BSP»** рядом с кнопкой загрузки. Ручной импорт
не нужен. Файлы поставляются в `web/hlstatsimg/heatmap-geometry/cstrike/`,
изображения — в `heatmaps/src/cstrike/`, привязка — в `sql/install.sql`.
После обычной чистой установки с этими каталогами доступны те же шаблоны.
При замене изображения шаблон показывается только при совпадении его контрольной
суммы; для другого изображения используйте ручной импорт подходящего SVG.
Следующая процедура нужна для подготовки дополнительных карт.

Для каждой карты нужны три файла с одинаковым именем: `maps/<карта>.bsp`,
`overviews/<карта>.bmp` и `overviews/<карта>.txt`. Из корня проекта выполните:

```powershell
python scripts/heatmap_import_goldsrc.py --game-dir "C:/Program Files (x86)/Steam/steamapps/common/Half-Life/cstrike" --output "tmp/native-overviews"
```

Папка результата должна быть новой или пустой. Инструмент читает игру, готовит
изображения и настройки, но сам не меняет сайт или базу данных. Нужны зависимости
Python проекта и Pillow; сопоставление изображений через OpenCV здесь не требуется.

В папке каждой карты появятся JPEG, `registration-report.json`,
`bsp-served-geometry.svg` и картинка с наложением контуров. В админке откройте
настройки теплокарт, выберите карту и загрузите подготовленный JPEG. В разделе
импорта выберите JSON с настройками и SVG с геометрией. Проверьте совмещение
контуров с изображением и контрольные точки перед сохранением привязки.
Изображение нельзя обрезать или растягивать после подготовки отчёта.

Этажи, их диапазоны высоты и допустимые области/стены задаются в
[редакторе этажей](heatmap-regions-and-scale.md). SVG служит ориентиром: он
содержит также крыши и перекрытия, поэтому не становится автоматически маской стен.

8 сентября подготовлены и установлены в локальной версии на порту 8382 все
25 совпавших карт из игры пользователя, включая новый inferno. См.
[результаты и обзор карт](audits/modern-heatmap-explorer/steam-maps-20260908/README.md).
Для этих новых изображений действуют новые настройки; значения для старого JPG
de_dust2 из следующего исторического раздела больше к ним не относятся.

## Проверка de_dust2 от 7 сентября 2026

В [отчёте](audits/modern-heatmap-explorer/bsp-registration-20260907/registration-report.json)
сохранены контрольные суммы BSP/BMP/TXT/JPG и точные коэффициенты. В
[схеме](audits/modern-heatmap-explorer/bsp-registration-20260907/bsp-served-geometry.svg)
показана извлечённая геометрия без игровой текстуры.

Извлечено 5130 поверхностей. При сопоставлении картинок найдено 661 соответствие;
441 использовано как надёжные точки подбора, 114 из 136 отложенных точек совпали
с точностью до 2 пикселей. Средняя квадратическая ошибка этих 114 точек —
0,629 пикселя. Это проверка привязки изображений; отдельной приёмкой реальных
событий она не является.

Повторные признаки в одной физической точке любого из двух изображений
объединяются в пространственные группы до разделения данных. Поэтому один
признак с разными направлениями не попадает одновременно в подбор и проверку.

Для зафиксированного JPG 1280×1024 получены настройки-кандидат:

```text
xoffset=2216, yoffset=-4371, scale=5.078819835144061
flipx=1, flipy=0, rotate=1
cropx1=cropx2=cropy1=cropy2=0
```

Они подходят только для файлов с контрольными суммами из отчёта. Проверка
рабочей Python-функцией на 3229 координатах BSP дала максимальное отличие
1,416 пикселя от непрерывного преобразования из-за целочисленного округления.

## Техническое приложение

Инструмент читает **только GoldSrc BSP v30**, проверяет границы и пересечения
секций файла и ссылки граней на вершины. Source BSP здесь не поддерживается.
Секции геометрии описаны в [исходниках Valve](https://github.com/ValveSoftware/halflife/blob/master/utils/common/bspfile.h).

Для оригинального GoldSrc BMP шириной W и высотой H=3W/4:

```text
s = 8192 / (ZOOM × W)             # игровых единиц на пиксель
ROTATED=1: u=W/2+(X-originX)/s; v=H/2-(Y-originY)/s
ROTATED=0: u=W/2-(Y-originY)/s; v=H/2-(X-originX)/s
```

Это следует из `DrawOverviewLayer` в
[SDK Valve](https://github.com/ValveSoftware/halflife/blob/master/cl_dll/hud_spectator.cpp).
`ORIGIN` — центр обзора, `ZOOM` не равен числу игровых единиц на пиксель.
После этого отдельно применяются масштаб и смещение BMP→JPG. Нельзя заменять
размер оригинального BMP размером произвольного JPG с полями.

Для Source исходная привязка отличается:
`u=(X-pos_x)/scale`, `v=(pos_y-Y)/scale` в виртуальном поле 1024×1024.
Поле `rotate` в Source относится к отображению всей карты в панели, а не к
повороту точек поверх неизменённой текстуры. Это видно в `WorldToMap` и
`MapToPanel` в [SDK Source](https://github.com/ValveSoftware/source-sdk-2013/blob/master/src/game/client/game_controls/MapOverview.cpp).

На многоэтажных картах одинаковые X/Y могут принадлежать разным этажам.
Нужны отдельный выбор диапазона Z и подходящий обзор этажа. Проекция всех
поверхностей BSP сверху не заменяет эту проверку.
