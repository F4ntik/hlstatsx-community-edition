# Валидация миграции `hlstats_py`

Этот документ описывает вспомогательный инструментарий для проигрывания
записанных UDP-пакетов через Python-пайплайн обработки событий. Цель —
подтвердить эквивалентность с Perl-версией `hlstats.pl` на выборке
канонических логов и сформировать чек-лист приёмки.

## Компоненты

* `scripts/hlstats_py/validation.py` — модуль с классами `ReplayRunner`,
  `ReplayDatabase` и `ReplayAdapter`. Они позволяют запускать
  нормализацию событий и слой записи (`EventStorage`) без подключения к
  MySQL, фиксируя все SQL-запросы и агрегированные показатели.
* `ReplaySnapshot` — структура с итоговыми счётчиками игроков, оружия,
  действий и списками вставленных событий (фраги, чаты, подключения,
  админ-лог).
* `ReplayResult.executed_queries` — последовательность SQL-запросов в том
  порядке, в котором их вызвал слой хранения. Это помогает сравнивать
  Python- и Perl-реализации.

## Тестовый сценарий

Файл `scripts/hlstats_py/tests/test_validation.py` содержит базовый
реплей из девяти пакетов `PROXY`, включающий события всех ключевых
категорий: подключение, чат, убийство, суицид, действие игрока,
триггер мира и административную запись. Проверяются следующие
инварианты:

* корректное разрешение игроков по `uniqueId`, включая обновление
  `lastAddress`;
* учёт фрагов (в том числе суицида) и оружия (`ak47`, `worldspawn`);
* начисление очков и счётчик действий `planted_bomb` и `Round_Start`;
* запись чатов, подключений и дисконнектов с ожидаемыми параметрами;
* формирование административного события из обобщённой строки лога;
* факт исполнения SQL-запросов `lastAddress` и `hlstats_Events_Admin`.

Запуск сценария:

```bash
PYTHONPATH=scripts python -m pytest scripts/hlstats_py/tests/test_validation.py
```

## Чек-лист приёмки миграции (задача 9.4)

1. Набор реплеев покрывает каждую категорию событий и проверяет
   сопоставление с ожидаемыми счётчиками игроков.
2. Запросы на обновление БД соответствуют последовательности Perl-версии
   (проверяется сравнением `executed_queries`).
3. Документация описывает процедуру запуска, структуру снапшота и
   интерпретацию результатов.
4. Все автоматизированные проверки входят в CI через `pytest`.

При необходимости можно расширять тесты новыми трассами, сохраняя формат
`datagrams` и проверки поверх `ReplaySnapshot`.
