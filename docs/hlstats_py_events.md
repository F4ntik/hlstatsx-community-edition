# Обработчики событий `hlstats_py`

Документ описывает архитектуру пакета `scripts/hlstats_py/events`, который
переносит обработчики игровых событий из `hlstats.pl` в Python. Этот слой
использует результаты парсинга протокола (см. `docs/hlstats_py_protocol.md`) и
нормализует их до структуры, пригодной для последующей записи в базу данных.

## Основные компоненты

* `EventDispatcher` — маршрутизатор, который принимает `LogEvent` и
  последовательно передаёт его зарегистрированным обработчикам. Если ни один
  обработчик не вернул результат, используется запасной (`fallback`) или
  возбуждается исключение `EventProcessingError`.
* `EventHandler` — интерфейс обработчика. Конкретные реализации находятся в
  `handlers.py` и соответствуют категориям событий (`Kill`, `Trigger`, `Chat`,
  `Connect`, `Disconnect`, `World`, `Generic`). Каждая реализация возвращает
  `EventUpdate` с категорией (`EventCategory`), нормализованным кодом события
  (`event_code`) и дополнительными атрибутами.
* `GameSchema` — контейнер с определениями оружия и игровых действий для
  конкретной игры. Он обеспечивает разрешение псевдонимов и локализованных
  названий, чтобы сохранить совместимость с текущими конфигурациями.
* `LocalizationCatalog` — словарь шаблонов сообщений, который позволяет
  формировать текстовые уведомления и поддерживает механизм иерархического
  поиска (`kill.ak47` → `kill` → `__default__`).
* `EventContext` — данные окружения (идентификатор сервера, код игры, схема и
  локализация), которые передаются обработчикам вместе с каждым событием.

## Поток обработки

1. UDP-пакет от прокси разбирается функцией `parse_proxy_envelope`.
2. Полезная нагрузка парсится через `parse_log_event`, результат — `LogEvent`.
3. `EventDispatcher` получает `LogEvent` и `EventContext` (включающий
   `GameSchema` и `LocalizationCatalog`).
4. Специализированный обработчик формирует `EventUpdate`, добавляя
   нормализованные атрибуты (например, `weapon_code`, `headshot`, `team_only`).
5. Следующий слой (задача 9.3) сможет преобразовать `EventUpdate` в SQL-запросы
   и обновить таблицы `hlstats_Events_*`.

## Расширение

* Новые игры добавляются через расширение `GameSchema` дополнительными
  определениями оружия и действий. Схема может быть собрана из таблиц MySQL или
  конфигурационных файлов.
* Для поддержки новых типов событий реализуйте новый обработчик, объявите
  `supported_types` и зарегистрируйте его в `EventDispatcher`.
* Локализация дополняется шаблонами в `LocalizationCatalog`. При отсутствии
  точного ключа используется ближайший по иерархии или значение по умолчанию.

## Связь с исходным Perl-кодом

* Логика обработки убийств, триггеров и глобальных событий отражает функции из
  `HLstats_EventHandlers.plib` и использует те же коды оружия/действий.
* Шаблоны сообщений повторяют подход Perl-версии с возможностью локализации и
  последующей отправки в HUD/чат игроков.
