# Слой хранения событий `hlstats_py`

Документ описывает модуль `scripts/hlstats_py/storage.py`, который отвечает за
запись нормализованных игровых событий в базу данных HLstats. Этот слой
использует `SyncDatabaseAdapter` из Python-версии прокси-демона и обеспечивает
совместимость с таблицами, которые ранее обновлялись скриптом `hlstats.pl`.

## Основные компоненты

* `EventStorage` — фасад, принимающий `EventUpdate` и `EventContext`. Внутри он
  определяет целевые таблицы MySQL для события, разрешает идентификаторы игроков
  и оружия, а затем выполняет соответствующие SQL-операции.
* Кэш игроков — позволяет повторно использовать ID игрока в рамках одного цикла
  обработки, чтобы минимизировать количество запросов к таблицам
  `hlstats_PlayerUniqueIds` и `hlstats_Players`.
* Кэш действий — хранит соответствия кодов действий (`planted_bomb`,
  `Round_Start` и т. д.) их идентификаторам в таблице `hlstats_Actions`.

## Поток обработки событий

1. Полученный `EventUpdate` содержит категорию (`FRAG`, `ACTION`, `CHAT` и т. д.),
   нормализованные коды, время и дополнительные атрибуты.
2. `EventStorage` разрешает игроков по `uniqueId` (SteamID) или имени и при
   необходимости создаёт записи в `hlstats_Players`, `hlstats_PlayerNames` и
   `hlstats_PlayerUniqueIds`.
3. В зависимости от категории формируются вставки/обновления:
   * Фраги — `hlstats_Events_Frags`, счётчики `kills`, `deaths`, `suicides` и
     статистика оружия (`hlstats_Weapons`).
   * Игровые действия — `hlstats_Events_PlayerActions` или
     `hlstats_Events_PlayerPlayerActions`, увеличение счётчиков в
     `hlstats_Actions` и, при наличии очков, корректировка `skill` игрока.
   * Чат и подключение — таблицы `hlstats_Events_Chat`,
     `hlstats_Events_Connects`/`Disconnects`, обновление `lastAddress`.
   * Смена команды и глобальные события — `hlstats_Events_ChangeTeam` и
     действия с нулевым `playerId`.
   * Прочие события — `hlstats_Events_Admin` с исходным сообщением.
4. Все запросы выполняются через соединение, предоставленное адаптером прокси.

## Гарантии и транзакции

* Соединение открывается через `SyncDatabaseAdapter.connection()`, который уже
  реализует ретраи и настройку `autocommit` на уровне драйвера `mysqlclient`.
* Каждое событие записывается серией коротких операций. Несмотря на то, что
  используемые таблицы (`MyISAM`) не поддерживают транзакции, модуль гарантирует
  детерминированный порядок запросов и повторное использование соединения, что
  облегчает последующий аудит и отладку.
* При ошибке любой операции возбуждается `StorageError`; вызывающий код может
  логировать её и повторить обработку с той же UDP-строкой.

## Как использовать

```python
from proxy_daemon_py.db import SyncDatabaseAdapter, DatabaseConfig
from hlstats_py import EventStorage

adapter = SyncDatabaseAdapter(DatabaseConfig(...))
storage = EventStorage(adapter)

update = dispatcher.dispatch(log_event, context)
storage.record(update, context)
```

Контекст (`EventContext`) должен содержать идентификатор сервера, код игры и
название текущей карты (`extras={"map": ...}`), чтобы вставки в таблицы
сохраняли связь с источником события.

Таким образом завершена задача 9.3: реализован слой записи событий Python-версии
`hlstats`, использующий адаптеры БД прокси-демона, с описанием гарантий и
автотестами, проверяющими формирование SQL-запросов.
